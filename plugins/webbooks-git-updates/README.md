# Webbooks Git Updates 1.0.0

Окремий WordPress-плагін для оновлення теми `webbooks` з публічного репозиторію `homeandriy/webbooks`. PHP 8.2+, WordPress 6.5+. Мультисайт не підтримується.

## Встановлення

Скопіюйте цю папку в `wp-content/plugins/webbooks-git-updates` або завантажте ZIP плагіна через **Плагіни → Додати плагін → Завантажити плагін**. Активуйте **Webbooks Git Updates**.

**Webbooks Git → Налаштування**: увімкнення перевірок, назва гілки (типово `main`). Перевірка запланована двічі на добу через WP-Cron; її фактичний час залежить від відвідувань сайту або серверного запуску cron.

**Webbooks Git → Статистика**: встановлена й доступна версії, commit, лічильники перевірок, помилок, завершених встановлень та останні 50 подій. Ручна перевірка — не частіше разу на хвилину.

## Підготовка оновлення теми

1. Підвищте й синхронізуйте версії теми у `functions.php` і двох заголовках `style.css`; оновіть `CHANGES.md` та `README.txt`.
2. Зберіть production-ресурси та релізний ZIP за правилами `docs/theme-updates.uk.md`.
3. Опублікуйте GitHub Release з тегом `vX.Y.Z` і asset **webbooks-theme-release.zip**. Архів має містити кореневу папку `webbooks/`, збіг версії, `functions.php`, `dist/.vite/manifest.json` і `dist/.vite/build-tag`.
4. У гілці, налаштованій у плагіні, має бути така сама версія `style.css`.

Workflow `.github/workflows/theme-release.yml` автоматизує складання й публікацію ZIP після push тега `vX.Y.Z`, коли сам workflow уже опублікований у GitHub. Наявний тег без цього workflow не створить asset заднім числом.

Плагін помічає **підвищення версії**, а не кожен commit. Якщо нова версія є в Git, але ZIP ще відсутній, повідомлення пояснює очікування. Коли ZIP готовий, адміністратор отримує кнопку **Встановити оновлення**. Встановлення виконує штатний WordPress Theme Upgrader із перевіркою прав, nonce і структури архіву. Автоматичне встановлення теми вимкнене, доки перевірки плагіна увімкнені.

Оновлення замінює локальні файли теми. Перед встановленням потрібна резервна копія. Зміни контенту, міграції БД та видалення старих папок тем плагін не виконує.

Для приватної перевірки можна задати `WEBBOOKS_GITHUB_TOKEN` у `wp-config.php`; токен не зберігається в налаштуваннях чи журналі. Завантаження приватних release assets не підтримується: ZIP має бути доступним без авторизації.

Не вмикайте одночасно інший updater для цієї теми. При помилці GitHub або метаданих старших за добу встановлення через плагін недоступне. Деактивація прибирає cron; налаштування та журнал зберігаються.

## Локальна перевірка

Після підготовки WordPress у disposable середовищі `tests/compose.yml`:

```bash
docker compose -p codex-webbooks-tests -f tests/compose.yml run --rm --no-deps --entrypoint php tests /theme/tests/git-updates.php
```

Тести використовують mocked GitHub API й відмовляються змінювати БД з іншою назвою, ніж `webbooks_tests`.

## Ручні UI-сценарії

- Адміністратор відкриває Налаштування, змінює гілку й зберігає: попередній пакет скинуто; неправильна гілка дає помилку.
- Статистика → Перевірити зараз: POST із nonce, повернення на Статистику, нова подія й час перевірки.
- Версія без ZIP: повідомлення про очікування без кнопки встановлення.
- Версія з ZIP: повідомлення з посиланням; WordPress перевіряє права й nonce перед оновленням.
- Неправильна версія або незбудований архів: встановлення зупинене до заміни теми.
- Неадміністратор не має меню налаштувань; повідомлення про оновлення бачить лише користувач із `update_themes`.
- Вимкнення перевірок або деактивація: запланований hook плагіна відсутній.
